# Save=BF16 的 EP4 / EP8 精度与性能补验（2026-11-06）

本轮 **16/16 条精度通过，24/24 个性能作业完成并通过身份及样本检查**。四个常用 shape 的新旧 BF16
前反向合计耗时差异为 **-0.347%～-0.053%**；同数值 FP32 p 相比新 BF16 为 **+0.020%～+0.201%**。
本轮结果支持“旧 BF16 与新 BF16 性能接近”的判断，这些小幅负值不作为加速收益。

本报告与数据仅用于训练协作分支，**不进入 main 或 lueelu/DeepEP 的正式提交**。
保持 [PR #20](https://github.com/xixing-321/DeepEP/pull/20) 为 Draft，本轮不合并。
硬件地址、容器标识、个人路径、完整日志和原始张量保留在私有证据中。

本页 16 条精度按各自实际输入 p 构建真值。[统一原始 FP32 p 基准的精度收益对照](TopKweight统一FP32基准精度对照_20261106.md)另行记录 EP8/M4096/H7168 的共同真值结果与 dp 评价口径；两轮验收范围分别保留。

## 性能方法与完整分项

四个 shape 为 EP4/EP8、每源 M4096、TopK6、每 rank 四专家、save=bf16；H/F/clipping 与上表相同。
每 shape 顺序固定为 **ABCCBA**，共 24 个串行作业，分别重装对应完整 wheel 并新建执行进程。
所有性能窗口在同一台机器、同一个容器及固定 runtime 完成，未混入其他环境或历史 pilot。

[inputs.json](data/topk_dtype_default_20261106/inputs.json) 保留本轮四个 shape 的 CPU 生成审计：
A/B/C 的 X、dY、W、路由索引及 counts 原始位相同，p 转 FP32 后数值相同；A/B 的 p 均以 BF16 保存，C 为 FP32。
其中还记录实际 CPU 输入生产库的文件大小和哈希。它证明同一冻结 `make_inputs` 的生成审计，
不是逐性能作业的运行时张量抓取；审计 SHA 逐作业与本轮准备记录绑定。

计时统一使用冻结入口的同步 NPU Event 区间，包含 Host 工作导致的设备流等待。
输入生成、参考计算、报告、wheel 安装、计时前清梯度和 loss 构造不在区间内。
每窗口对 F、B 和逐次配对 T 分别取“每 rank 20 样本中位数 → 跨 rank 最大值”，
再对同 variant 两个窗口取中位数。T 使用同迭代 F+B 样本，**不相加 F/B 的中位数**。
这是公开调用的同口径对照，不是纯 kernel 计时，也不与 PR #19 的独立 complete 口径混合。

## 环境、调试选项与资源边界

平台为 Ascend950，CANN 9.2.0/B234，Python 3.12.13、Torch 2.10.0+cpu、torch_npu 2.10.0.post4、
glibc 2.38、CXX11 ABI=true；驱动 `26.2.0.b020`，实际 HAL SHA256 为
`ab759e7165f18ca68640583585650327b9ec34893fd611e9af3820b44d213450`。
CATLASS 固定 `2b4bd7cbf7e67ebab23d7d5a99d472c83f90d9a1`，SHMEM 固定 `4dd80e2129da42bd773982c2bb3758af1ed0bba8`。
没有 CANN 9.2.1、多机或其他平台的实测结论。

精度最初环境 A 完成 4 smoke + 10 full，发现其他用户预检后停止后续准入；环境 B 补尾部两条。
二者使用同 wheel 和框架/SDK 版本，镜像不同：A=`84c38e63e0727d5026f5406419d571a00753095041193be69228b45d3e18504b`，
B=`3674ca831e2d09b535fbc27a57de6d420db30e8353d48ccbf33eb0b51715045a`。
精度 JSON 逐 case 绑定真实 context，**16 条精度不称同机完成**；性能 24 条全部在 B 完成。

新产品的实际 Torch CPU 检查 91 项通过。真实 EP2 独立 EP group 的 A/Gloo、B/Gloo、B/HCCL 专项均退出 0，
两 rank 通过：默认 False 每对前反向为 0 次 dtype collective，True 为 2 次；八组 save/clip/dtype
的同实例混合排队、逆序反向与串行六输出逐位一致；初始化调试配置、True 下跨 rank dtype/阶段错配，
以及非法 dtype 均在 native 入口前拒绝。该小形状专项不是独立 golden、整网验证或完整图身份/操作顺序协议。

旧调用不需增加必填参数，Python 类、forward 调用、SO 名称和导出符号保持兼容。
默认 `debug_collectives=False` 时，每次调用仍有本地 dtype 及既有 Host 输入校验，
框架负责各 rank 同一次调用 dtype 和相容调度顺序；需要定位时在所有 rank 一致设置 True。
初始化仍交换必要配置，不使用“上次 dtype 未变化则跳过 collective”之类的局部缓存。

本轮全程避开柜 2、柜 3，每个设备作业启动前检查卡、训练/CI/待启动任务、维护、驱动及端口。
性能完成前 9 项后曾因一条外部资源查询进程暂停，第 10 项尚未启动；等待该查询退出、重新通过门禁后，
显式恢复同一个批次。容器、软件、输入审计及原 9 项连续结果逐一核对，未覆盖或挑选已完成样本。
此过程保留暂停记录，不称 24 项无中断执行。全部作业结束后只停止自己的空闲验证容器，原始目录保留。
